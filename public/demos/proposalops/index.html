WHY

생성보다 근거 추적을 먼저 설계

생성형 AI는 문장을 자연스럽게 확장하는 데 강하지만, 제안서에서는 “어디까지가 과거 자료로 검증된 사실인지”를 잃으면 리스크가 됩니다. ProposalOps는 requirement → evidence → strategy → page → slide → visual 연결을 추적합니다.

DETERMINISTIC

Coverage Validator

RFP 필수 요구사항이 제안서 페이지 구조에 빠짐없이 매핑되었는지 검사합니다.

DETERMINISTIC

Provenance Gate

다른 요구사항의 evidence가 현재 페이지에 섞였는지, 허용되지 않은 근거 ID가 사용됐는지 차단합니다.

SEMANTIC QA

INVALID_REFERENCE

존재하는 근거를 인용했더라도, 실제 evidence가 지원하는 범위를 넘어 세부 내용을 확대하면 BLOCK 처리합니다.

TARGETED REPAIR

문제 범위만 재작성

전체 제안서를 처음부터 다시 생성하지 않고 QA가 지적한 page / strategy 범위만 재생성합니다.

VALIDATION

실제로 잡힌 오류

잘못된 근거 연결: R-202용 evidence가 다른 page에 사용되자 provenance gate에서 자동 차단했습니다.

근거 범위 초과: reference가 직접 지원하지 않는 “지도·예약 연결” 같은 구체 표현을 semantic QA가 INVALID_REFERENCE로 탐지했습니다.

수정 경로: QA → Repair Router → Targeted Repair → Merge Gate 순서로 문제 범위만 재작성하는 흐름을 실행했습니다.
