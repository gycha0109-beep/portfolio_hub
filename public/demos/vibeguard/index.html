확정 Finding 5건

각 항목은 Finding → Reproduction → Root Cause → Fix → 동일 조건 Re-test 순서로만 기록했습니다.

EVT-01

투표 없이 canonical vote event 위조 가능

CLOSED
FINDINGauthenticated client가 vote_submit을 직접 기록 가능

비즈니스 사실과 관찰용 analytics event가 같은 write path를 사용했습니다.

REPRODUCTIONvote 0 / vote_submit event 1

disposable Supabase에서 frozen baseline 그대로 재현했습니다.

ROOT CAUSE직접 INSERT grant + 느슨한 event 정책

user_id = auth.uid()만 만족하면 canonical event도 허용됐습니다.

FIXcanonical event를 submit_vote 내부로 이동

일반 이벤트는 allowlist RPC만 사용하고 vote_submit은 제외했습니다.

RE-TEST직접 위조 차단

최종 run에서 canonical vote event client forgery가 차단됨을 확인했습니다.

INT-01

vote와 canonical event가 서로 다른 상태로 남을 수 있음

CLOSED
FINDING실제 vote는 있는데 대응 event가 없는 상태 가능

두 write가 독립적으로 수행됐습니다.

REPRODUCTIONvote 1 / matching event 0

baseline DB에서 해당 불일치 상태를 만들 수 있었습니다.

ROOT CAUSEtransactional server-owned operation 부재

클라이언트가 durable write와 analytics write를 각각 처리했습니다.

FIXsubmit_vote() RPC로 원자화

vote insert와 canonical event를 같은 DB transaction에서 처리합니다.

RE-TEST중복 2회 호출 → vote 1 / event 1

첫 호출만 insert되고 두 번째는 idempotent하게 종료됩니다.

STO-01

unpublished entry 이미지가 public Storage bucket에 매핑

CLOSED
FINDING비공개 entry라도 image object 경로가 public bucket 사용

write ownership은 있었지만 read privacy가 bucket 공개 설정에 의존했습니다.

REPRODUCTIONunpublished=true + bucket.public=true

두 조건이 동시에 존재함을 disposable Supabase에서 확인했습니다.

ROOT CAUSEpublic bucket + read 경계 부재

entry visibility와 object visibility가 연결되지 않았습니다.

FIXprivate bucket + published/owner SELECT policy

공개 entry 또는 자신의 folder만 읽도록 바꿨습니다.

RE-TESTanon 비공개 차단 / owner 접근 유지

공개 객체는 anon 허용, 비공개 객체는 owner만 접근합니다.

QA-01

생성 저장소 자체 lint gate 실패

CLOSED
FINDINGbun run lint 실패

저장소가 제공한 품질 게이트 자체가 깨진 상태였습니다.

REPRODUCTION157 problems · 150 errors · 7 warnings

150 errors는 formatter violation으로 자동수정 가능 상태였습니다.

ROOT CAUSE생성 결과와 repository formatting rule 불일치

앱 기능과 별개로 CI에 바로 넣을 수 없는 상태였습니다.

FIXdeterministic formatter pass

repo formatter를 CI에서 실행해 formatting-only 변경을 분리했습니다.

RE-TESTstrict lint PASS

최종 pipeline에서는 continue-on-error 없이 통과합니다.

QA-02

생성된 routing smoke test 2/2 실패

CLOSED
FINDING정상 테스트 명령에서도 route smoke가 모두 실패

index와 not-found 두 테스트 모두 empty render로 timeout 됐습니다.

REPRODUCTION0 pass / 2 fail

expected null not to be null을 동일하게 확인했습니다.

ROOT CAUSErouter initial load 이전 렌더

test harness가 router.load() 완료를 기다리지 않았습니다.

FIXinitial router load 후 render

실제 앱 코드를 속이지 않고 smoke harness의 lifecycle을 맞췄습니다.

RE-TESTtest + production build PASS

최종 strict pipeline에서 둘 다 통과했습니다.
